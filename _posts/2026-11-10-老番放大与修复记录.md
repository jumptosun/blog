# 老番放大与修复记录：DVD 720×480 到 1440×1080

**适用片源**：2005 年前后的 NTSC DVD 动画，720×480，4:3，telecine  
**目标输出**：1440×1080，59.94fps，10bit HEVC

## 1. 概述

记录如何把一部 2005 年前后的 NTSC DVD 动画从 720×480 修复到 1440×1080。你可以按步骤执行，也可以在失败时跳到第 7 节回滚，或第 8 节故障排查。

流程只读取源文件。所有输出写到独立工作目录。每一步都有预期结果。没有看到预期结果时，不要进入下一步。

### 1.1 适用范围

这份流程针对特定的源和特定的目标。换源、换卡、换模型后，参数需要重新验证。

| 项目 | 适用 | 不适用 |
|---|---|---|
| 源分辨率 | 720×480，SAR 8:9，DAR 4:3 | 1920×1080、4K、竖屏 |
| 源编码 | MPEG-2，8bit 4:2:0 | VCD、RMVB、多次转录的烂源 |
| 场序 | 23.976 telecine，或少量真 interlaced | 纯 60i 实拍、混合帧率且无规律 |
| 内容 | 2D 动画，线条和色块为主 | 真人、强颗粒胶片、复杂纹理 |
| 目标 | 1440×1080，4:3，1080 线 | 1920×1080 16:9 |
| 预期 | 看得更舒服，保留原画风 | 接近官方重制版 |

如果源已经有官方 BD，直接找 BD。任何模型都比不上官方重制。

### 1.2 输出规格

输出规格固定，便于后续检查和播放器兼容。

| 项目 | 值 |
|---|---|
| 容器 | MKV |
| 视频编码 | HEVC Main10，`yuv420p10le` |
| 分辨率 | 1440×1080 |
| 显示比例 | 4:3，播放器左右加黑边 |
| 帧率 | 59.94fps，CFR |
| 色彩矩阵 | BT.709 |
| 色彩范围 | limited，`tv` |
| 音频 | 从源复制，或 Opus 256k |
| 字幕 | 外挂，最后用 `mkvmerge` 合入 |

1440×1080 是 4:3 的 1080 线，不是 1920×1080。不要为了“满屏”把它拉成 16:9。

文中的结论分四类。没有标记的句子是操作说明，不是实验结论。

| 标记 | 含义 |

### 1.4 模型与工具地图

模型发展可以分成四代。理解每一代解决什么问题，比记模型名字有用。

| 阶段 | 代表 | 关键变化 | 对老番的意义 |
|---|---|---|---|
| 2015–2018 | waifu2x | 卷积网络做 2x，退化以 bicubic 下采样为主 | 对干净截图有效，对 DVD 块效应和振铃无感 |
| 2018–2021 | ESRGAN | RRDB、感知损失、对抗损失 | 线条更锐，开始补结构，也开始编细节 |
| 2021–2022 | Real-ESRGAN、Real-CUGAN | 真实退化建模，动画特化 | 能应付真实烂源，CUGAN 把降噪做成档位 |
| 2023–2024 | APISR、AniSD、AnimeJaNai | 按制作流程或片源类型训练 | 从通用超分转向特定退化 |
| 2023– | SPAN、DAT/DAT2、RealPLKSR | 架构换代 | 重建更强，生态和算子支持还在补 |

当前没有通杀模型。先看源的退化类型，再看模型训练集，最后看速度。

| 目标 | 优先模型 | 代价 |
|---|---|---|
| 不改画风，只去瑕疵 | Real-CUGAN conservative、AniSD | 线条可能偏软，去伪影有限 |
| 更强重建，更锐 | APISR 2x、AnimeJaNai V2 | 可能改色调、改线条粗细 |
| 2000 年代 DVD/WEB 通用修复 | AniSD Suite | 主模型偏保守 |
| 1080p 上 4K | AnimeJaNai V3/V3.1 | 不适合 480p 的 2x |
| 先看效果 | Anime4K v4、`realesr-animevideov3` | 不是重建型模型 |

工具按控制力排序：

| 工具 | 用途 | 限制 |
|---|---|---|
| VapourSynth + vs-mlrt | 正式流程，串联和逐帧控制 | 环境复杂，需要写 `.vpy` |
| video2x | 30 秒样片，单模型粗修 | 不能 IVTC、deband、串联模型 |
| chaiNNer | 单帧或短片段调参 | 不适合整片批处理 |
| VapourKit | 不想写代码，但要预览对比 | 仍然是封装好的流程 |
| VideoJaNai | 只跑 AnimeJaNai 系 ONNX | 模型范围窄 |
| ComfyUI | 已经在玩 SD 的人顺手用 | 视频时间维处理弱 |

OpenModelDB 用来筛模型，不用来拜排名。每个模型页先看四行：Dataset、Dataset Size、Training HR size、License。预览图有一部分已经挂掉，模型页也可能落后于 GitHub release。以仓库 README 为准。

## 2. 前置条件

开始前先确认硬件、软件、磁盘和权限。任何一项缺失，都会在流程中段停下来。

### 2.1 硬件与系统

本文使用一台 AMD RX 6750 GRE 10G 的 Linux 机器。Windows 也能做，插件预编译覆盖更好。

| 项目 | 建议 | 说明 |
|---|---|---|

### 2.4 Linux 插件注意事项

Linux 下插件问题比 Windows 多。先看表，再决定是否继续。

| 问题 | 处理 |
|---|---|
| 旧插件目录不自动加载 | R74 后插件目录是 `<site-packages>/vapoursynth/plugins`；旧路径要设 `VAPOURSYNTH_EXTRA_PLUGIN_PATH` 或显式 `LoadPlugin` |
| vsrepo 没有 Linux 构建 | 先查 PyPI，再查 vsrepo，最后自己编译 |
| akarin 编译依赖麻烦 | 优先用 `vapoursynth-akarin` wheel；不行时用 `std.Expr` 兜底 |
| RIFE 找不到模型 | `models` 目录和 `.so` 放同一级 |
| 只有 `.dll` 没有 `.so` | 上游没发 Linux 构建，换插件或自己编 |
| 报 unsupported operator | 先查 ONNX 算子，不要先怀疑系统 |

R74 之后，`/usr/lib/vapoursynth` 里的插件不会自动生效。旧脚本里的 `LoadPlugin("/usr/lib/...")` 要么删掉，要么改成新路径。

vsrepo 的 Windows 覆盖率仍然高于 Linux。按 2026-11 的索引统计，259 个包中 206 个有 win64 构建，82 个有 Linux 构建。遇到缺的包，不要硬编译，先看 PyPI。

## 3. 源评估

先评估源，再决定流程。场序、VFR、矩阵这三项判断错，后面的工作基本要重来。

### 3.1 探针

先看容器和视频流的基本信息。

```bash
ffprobe -v error -select_streams v:0 \
  -show_entries stream=width,height,sample_aspect_ratio,\
display_aspect_ratio,r_frame_rate,avg_frame_rate,pix_fmt,\
field_order,color_space,color_transfer,color_primaries \
  -of default=noprint_wrappers=1 01/source.mkv
```

重点看四个字段：

| 字段 | 判断 |
|---|---|
| `sample_aspect_ratio` | 8:9、10:11、1:1 |
| `r_frame_rate` 与 `avg_frame_rate` | 不一致时，大概率 VFR |
| `field_order` | `progressive`、`tt`、`bb`、`unknown` |
| `color_space` | 经常是 `unknown`，DVD 按 BT.601 处理 |

预期结果：能确认分辨率、SAR、帧率、像素格式和场序。字段缺失时，不要猜，进入 3.2 和 3.3 实测。

### 3.2 场序判定

用 `IsCombed` 统计 combed 帧比例。脚本用 TDeintMod 的 `tdm.IsCombed`，参数和旧脚本一致。

```python
#!/usr/bin/env python3
# combed_test.py
# 用法: python combed_test.py 01/source.mkv
import sys
import vapoursynth as vs

if len(sys.argv) < 2:
    print("用法: python combed_test.py 01/source.mkv")
    sys.exit(1)

core = vs.core
core.max_cache_size = 8192  # MB，按内存调整

clip = core.bs.VideoSource(sys.argv[1])
combed_clip = core.tdm.IsCombed(
    clip,
    cthresh=6,
    blockx=16,
    blocky=16,
    chroma=False,
    mi=64,
    metric=0,
)

total = combed_clip.num_frames
combed_count = 0
error_count = 0

for n in range(total):
    try:
        frame = combed_clip.get_frame(n)
        if frame.props.get("_Combed", 0) == 1:
            combed_count += 1
    except Exception as exc:
        error_count += 1
        if error_count == 1:
            print(f"[WARN] frame {n}: {exc}", file=sys.stderr)
    if n % 500 == 0 and n > 0:
        print(f"  ... {n}/{total}", file=sys.stderr)

print(f"总帧数: {total}")
print(f"Combed 帧数: {combed_count}")
print(f"错误帧数: {error_count}")
if total > 0:
    ratio = combed_count / total
    print(f"Combed 比例: {ratio * 100:.4f}%")
    if ratio > 0.5:
        print("判定: 大概率 interlaced，走 QTGMC")
    elif ratio > 0.05:
        print("判定: 混合源或 telecine，检查 combed 帧分布")
    else:
        print("判定: 基本 progressive，跳过场序处理")
```

预期结果：输出 combed 比例。

| 比例 | 判断 | 下一步 |
|---|---|---|
| 大于 50% | 真 interlaced | QTGMC |
| 5% 到 50% | 混合源或 telecine | 检查是否每 5 帧一组 3:2 |
| 小于 5% | 基本 progressive | 跳过场序处理 |

阈值是经验值。真正可靠的是看 combed 帧的分布，不是只看总数。

### 3.3 VFR 与 CFR 判定

RIFE 的倍率按帧序号计算。VFR 源的时间间隔不一致，插出来的中间帧会落在错误时间点，表现为规律性抖动。

先看帧率：

```bash
ffprobe -v error -select_streams v:0 \
  -show_entries stream=r_frame_rate,avg_frame_rate,time_base \
  -of default=noprint_wrappers=1 01/source.mkv
```

两个帧率一致，时间戳间隔也稳定，就是 CFR，可以跳过转 CFR。两个帧率不一致，继续导出每帧时间戳：

```bash
ffmpeg -i 01/source.mkv -vf showinfo -f null - 2>&1 \
  | grep showinfo > 01/logs/showinfo.log
```

用脚本统计相邻 `pts_time` 的间隔：

```python
#!/usr/bin/env python3
# analyze_fps.py
# 用法: python analyze_fps.py 01/logs/showinfo.log
import math
import re
import sys

RE_LINE = re.compile(
    r"n:\s*(?P<n>\d+)\s+"
    r"pts:\s*(?P<pts>-?\d+)\s+"
    r"pts_time:(?P<pts_time>-?[0-9.]+)\s+"
    r"duration:\s*(?P<duration>-?\d+)\s+"
    r"duration_time:(?P<duration_time>-?[0-9.]+)"
)

def parse(lines):
    frames = []
    for line in lines:
        match = RE_LINE.search(line)
        if match:
            frames.append((
                int(match.group("n")),
                float(match.group("pts_time")),
                float(match.group("duration_time")),
            ))
    return frames

def main():
    if len(sys.argv) > 1:
        lines = open(sys.argv[1], encoding="utf-8")
    else:
        lines = sys.stdin

    frames = parse(lines)
    if len(frames) < 2:
        print("帧数不足")
        return

    intervals = []
    for index in range(1, len(frames)):
        intervals.append((index, frames[index][1] - frames[index - 1][1]))

    average = sum(delta for _, delta in intervals) / len(intervals)
    stddev = math.sqrt(
        sum((delta - average) ** 2 for _, delta in intervals) / len(intervals)
    )
    threshold = max(average * 0.05, 0.0005)

    print(f"总帧数: {len(frames)}")
    print(f"平均间隔: {average:.6f}s ({1 / average:.3f} fps)")
    print(f"标准差: {stddev:.6f}s")
    print(f"异常阈值: ±{threshold:.6f}s")

    anomalies = [
        (index, delta)
        for index, delta in intervals
        if abs(delta - average) > threshold
    ]
    if not anomalies:
        print("未检测到异常间隔")
        return

    print("异常点:")
    for index, delta in anomalies[:50]:
        ratio = (delta - average) / average * 100
        print(f"  帧 {index} 间隔 {delta:.6f}s 偏差 {ratio:+.2f}%")

    print("连续异常区域:")
    indexes = sorted(index for index, _ in anomalies)
    start = end = indexes[0]
    for index in indexes[1:]:
        if index == end + 1:
            end = index
        else:
            print(f"  帧 {start} 到 {end}")
            start = end = index
    print(f"  帧 {start} 到 {end}")

if __name__ == "__main__":
    main()
```

预期结果：标准差接近 0 时是 CFR；标准差明显大于 0 且异常成段时是 VFR。容器时间戳抖动也会让标准差非 0，要结合异常区间判断。

### 3.4 矩阵与 range

DVD 是 BT.601，HD 是 BT.709。矩阵用错不会报错，只会让颜色偏。

| 源 | 矩阵 | VapourSynth 值 |
|---|---|---|
| NTSC DVD | SMPTE 170M，BT.601 525 | `6` |
| PAL DVD | BT.470BG，BT.601 625 | `5` |
| Blu-ray / WEB 1080p | BT.709 | `1` |
| UHD | BT.2020 NCL | `9` |

输入按源，输出按目标。解码 DVD 用 `6`，编码 HD 用 `1`。只改一头，比不改更糟。

VapourSynth 的 resize 优先使用帧属性 `_Matrix` 和 `_Range`，`matrix_in` 不覆盖它们。DVD 元数据经常是 unknown 或写错，先改属性：

```python
clip = core.std.SetFrameProps(clip, _Matrix=6, _Range=0)
```

`_Range=0` 是 limited，`_Range=1` 是 full。R74 之后使用 `_Range`，旧的 `_ColorRange` 已废弃，两者的 0/1 含义相反。

严格色彩管理还要转 primaries 和 transfer。本文只转 matrix。转 primaries 容易把色彩改得更明显，我没有做色度计对比。这条是取舍。

### 3.5 决策表

把 3.1 到 3.4 的结果填进表，再决定流程。

| 源特征 | 处理 |
|---|---|
| combed 大于 50% | QTGMC，`FPSDivisor=2` |
| combed 5% 到 50%，有 3:2 规律 | TIVTC 两遍法 |
| combed 小于 5% | 跳过场序处理 |
| r/avg 帧率不一致 | 先 IVTC，再转 CFR |
| 已经是 CFR | 跳过转 CFR |
| 720×480，SAR 8:9 | 拉伸到 720×540 |
| 720×480，SAR 1:1 | 先确认 DAR，再决定是否拉伸 |
| 720×576 PAL | 不在本文范围，矩阵用 5 |

## 4. 操作流程

按顺序执行。每一步都有预期结果。失败时先停，不要带着错误进入下一步。

### Step 1：备份与建目录

先建工作目录，复制源文件，确认磁盘空间。后续所有命令只写工作目录。

```bash

cp -n 01.mkv 01/source.mkv
df -h .
```

预期结果：`01/source.mkv` 存在，磁盘可用空间大于 60GB。

### Step 2：场序处理

按 3.2 和 3.5 的结果选择 IVTC 或 QTGMC。telecine 必须做 IVTC，不要做去交错。

**IVTC 第一遍：分析。**

```python
# pulldown_pass1.vpy
import vapoursynth as vs

core = vs.core
clip = core.bs.VideoSource(input)

core.tivtc.TDecimate(
    core.tivtc.TFM(clip, output="matches.txt"),
    mode=4,
    output="metrics.txt",
).set_output()
```

```bash
vspipe -p -a input=01/source.mkv -c y4m pulldown_pass1.vpy - \
  | ffmpeg -f yuv4mpegpipe -i - -f null -
```

**IVTC 第二遍：应用。**

```python
# pulldown_pass2.vpy
import vapoursynth as vs

core = vs.core
clip = core.bs.VideoSource(input)

clip = core.tivtc.TFM(clip, input="matches.txt")
clip = core.tivtc.TDecimate(
    clip,
    mode=1,
    input="metrics.txt",
    tfmIn="matches.txt",
)
clip.set_output()
```

```bash
vspipe -p -a input=01/source.mkv -c y4m pulldown_pass2.vpy - \
  | ffmpeg -f yuv4mpegpipe -i - \
      -c:v ffv1 -level 3 -coder 1 -context 1 \
      -pix_fmt yuv420p10le -f matroska -y 01/01_ivtc.mkv
```

预期结果：`01/01_ivtc.mkv` 的帧数约为源的 4/5，帧率为 23.976。用 `ffprobe` 确认。

失败时：TFM 报 `order` 错误，说明源没有 `_FieldBased` 属性。加 `order=1` 表示 TFF，`order=0` 表示 BFF。IVTC 后仍有 combed 帧，检查 TFM 的 matches 和 combed 帧位置。

**真 interlaced 才用 QTGMC：**

```python
# qtgmc_restore.vpy
import vapoursynth as vs
import havsfunc as haf

core = vs.core
clip = core.bs.VideoSource(input)
clip = core.std.SetFrameProps(clip, _Matrix=6, _Range=0)

if clip.width % 4 or clip.height % 4:
    clip = core.std.CropAbs(
        clip,
        width=clip.width - clip.width % 4,
        height=clip.height - clip.height % 4,
    )

clip = haf.QTGMC(clip, Preset="Slow", TFF=True, FPSDivisor=2)
clip = core.resize.Bicubic(
    clip,
    format=vs.YUV420P10,
    matrix_in=6,
    matrix=1,
    range_s="limited",
)
clip.set_output()
```

预期结果：帧率为 29.97，画面无梳状。`FPSDivisor=2` 把 QTGMC 的双倍帧率减半。BFF 源把 `TFF=True` 改成 `TFF=False`。

### Step 3：VFR 转 CFR

只有 3.3 判定为 VFR 时才执行。CFR 是后续插帧的前提。

```bash
ffmpeg -i 01/01_ivtc.mkv -fps_mode cfr -r 24000/1001 \
  -c:v ffv1 -level 3 -coder 1 -context 1 \
  -c:a libopus -b:a 256k \
  -af "aresample=async=1000" -ac 2 -ar 48000 \
  01/01_cfr.mkv
```

预期结果：`r_frame_rate` 和 `avg_frame_rate` 一致，时长与源一致，音频存在。

注意音频：`ffmpeg` 的音频来自输入文件。如果 `01_ivtc.mkv` 是 `vspipe` 出来的无音频中间文件，先把源音频映射回来：

```bash
ffmpeg -i 01/01_ivtc.mkv -i 01/source.mkv \
  -map 0:v:0 -map 1:a? -c:v copy -c:a copy \
  01/01_ivtc_audio.mkv
```

失败时：音频漂移就保留 `aresample=async=1000`；如果源本身是 VFR，检查异常区间，不要用平均帧率硬套。

### Step 4：几何处理

把 720×480 拉伸到 720×540，得到方形像素。再用 2x 模型放大到 1440×1080。

```python
# upscale.vpy 的第 1 段
clip = core.bs.VideoSource(input)
clip = core.std.SetFrameProps(clip, _Matrix=6, _Range=0)
clip = core.resize.Spline36(clip, width=720, height=540)
```

预期结果：把几何段单独存成 `geometry_test.vpy` 并 `set_output()` 后，`vspipe -a input=01/01_cfr.mkv --info geometry_test.vpy` 显示 720×540，SAR 1:1。

失败时：SAR 不是 1，检查 `_SARNum` 和 `_SARDen`。如果源是 PAL 720×576，本文的比例不适用。

不要先降到 640×480。720 到 640 会丢掉 80 列采样，再让模型放大回来，等于先丢信息再补。

如果要裁掉 DVD 两侧 padding，先确认活动画面是 704×480。裁到 704×480 后，SAR 要改成 10:11，再 resize 到 704×528。这样输出是 1408×1056，还要 pad 到 1440×1080。为了 1% 的像素折腾一圈，本文不采用。

Spline36 是本文的默认核。VapourSynth 没有 Spline26，只有 Spline16、Spline36、Spline64。720 到 540 是 1.125 倍拉伸，换核函数对观感影响小，决定观感的是后面的模型。

### Step 5：预处理

顺序是 deband、dering、denoise。去色带必须在放大前做。模型会把 8bit 色阶断层当成边缘重建，放大后再 deband 已经晚了。

**去色带：**

```python
clip = core.f3kdb.Deband(
    clip,
    y=48,
    cb=24,
    cr=24,
    grainy=32,
    grainc=16,
    dynamic_grain=False,
)
```

**去振铃：**

```python
clip = core.lghost.LGhost(
    clip,
    mode=[1],
    shift=[5],
    intensity=[23],
)
```

**降噪：**

传统方法优先。SMDegrain 和 BM3D 快、可控、不改结构。模型降噪可以跑，但本文不推荐整片串联。

- DPIR 对色块和振铃有效，对交错边缘无能为力，6750 GRE 上不到 10fps，太慢。
- SCUNet 在我这里没跑起来，ncnn 后端算子问题，没有继续排查。

预期结果：色带明显减少，线条没有明显被吃掉，画面没有变成塑料。用 30 秒样片对比。

失败时：deband 过头就降低 `grainy` 或阈值；dering 过头就降低 `intensity`；降噪过头就换更轻的档位。

如果觉得线条太软，可以短片段试 AWarpSharp2、CAS、TAAmbk。线条加粗和锐化很容易改画风，本文不把这些处理放进正片主链。

### Step 6：转 RGBS

模型要求浮点 RGB。先按源矩阵解码，再进入模型链。

```python
clip = core.resize.Bicubic(
    clip,
    format=vs.RGBS,
    matrix_in=6,
    range_in_s="limited",
)
```

预期结果：把 RGB 转换段单独存成 `rgb_test.vpy` 并 `set_output()` 后，`vspipe -a input=01/01_cfr.mkv --info rgb_test.vpy` 显示 RGBS，32bit float。

失败时：颜色偏，先检查 `_Matrix` 和 `_Range` 帧属性。帧属性优先于 `matrix_in`，属性错了，参数不会生效。

RIFE 只接受 RGBS。CUGAN 接受 RGBH 和 RGBS。NCNN_VK 后端不暴露 `output_format`，`fp16=True` 只影响后端内部计算。整条链统一用 RGBS，更稳。

### Step 7：2x 放大

用 `vsmlrt.inference` 调用 AniSD。第一次先用整帧或 1024×1024 分块，显存不够再降。

```python
import vsmlrt

clip = vsmlrt.inference(

```

预期结果：输出 1440×1080。检查渐变区有没有等间距接缝。

失败时：显存不足就把 `tilesize` 降到 512。接缝明显就把 `overlap` 加到 32。报 unsupported operator，先用 `model_test.py` 查 ONNX 算子。

### Step 8：RIFE 2.5x 插帧

用独立 RIFE 插件，不用 `vsmlrt.RIFE`。`vsmlrt.RIFE` 在 NCNN_VK 后端缺 `GridSample`，跑不了。

clip = core.rife.RIFE(

预期结果：23.976 × 5/2 = 59.94fps。帧数约为输入的 2.5 倍。

失败时：有鬼影就把 4.26 换回 4.25。本文默认 `model=69`，即 4.25。快速横摇仍然有重影时，降低倍率或对该段禁用插帧。

## 5. 参数与模型参考

这一节是查表用的。执行流程时不需要从头读，遇到选择再回来查。

### 5.1 选模型的顺序

先看源的退化类型，再看模型训练集，最后看速度。不要先看排行榜。

1. 源是 DVD 还是 WEB。
2. 源是 480p 还是 1080p。
3. 源的主要问题是块、振铃、色带，还是模糊。
4. 你能接受多大的画风变化。
5. 你愿意等多久。

OpenModelDB 的模型页先看 Dataset、Dataset Size、Training HR size、License。模型页可能落后于仓库 README，以 README 为准。

### 5.2 放大模型

本文实际用过的模型如下。参数来自各模型官方页，速度只表示相对量级。

| 模型 | 基座 | 倍率 | 训练域 | 强项 | 弱项 |
|---|---|---|---|---|---|
| Real-CUGAN | waifu2x-cunet | 2/3/4 | 动画通用 | 保画风、线条稳 | 去伪影弱 |
| Real-ESRGAN animevideov3 | Compact | 4 | 动画视频 | 快、通用 | 4x 硬放大，细节有限 |
| Real-ESRGAN anime6b | RRDB | 4 | 动画通用 | 线条锐、重建强 | 重，容易改画风 |
| AnimeJaNai V2 | Compact | 2 | 1080p 动画 | 保细节 | 不是 SD 专用 |
| AnimeJaNai V3.0 | Compact | 2 | 1080p 动画 | 自然、保线条 | 不作为 SD 首选 |
| AnimeJaNai V3.1 | SPAN | 2 | 1080p 动画 | 更自然 | 不作为 SD 首选 |
| APISR 2x | RRDB-6blocks | 2 | 制作流程退化 | 重建强 | 可能改色调 |
| APISR 4x DAT | DAT-Small | 4 | 同上 | 重建能力最高 | 比 2x 慢约 20 倍 |
| AniSD Suite | SPAN 为主 | 2 | 2000s DVD/WEB | 不过锐、去块/去色带 | 线条偏保守 |
| Anime4K v4 | GLSL | 按档 | 动画 | 快 | 不是重建模型 |

几个容易记错的点：

- APISR 2x 是 RRDB-6blocks，4.47M 参数。4x 有 GRL 和 DAT-Small。DAT-Small 10.89M，官方 3090Ti 上 0.683s/256²，2x RRDB 是 0.010s/256²，差接近 20 倍。
- APISR 的 DAT 只有 4x，没有 2x。想用 DAT 做 2x，只能 4x 放大再降采样。
- AniSD Suite 有 15 个模型，覆盖 SPAN、Compact、SwinIR Small、CRAFT、DAT2、RPLKSR。主模型是 SPAN，48 通道。
- AnimeJaNai V3.0 是 Compact，V3.1 是 SPAN。V3 系主要面向 1080p 到 4K，不是 480p 的默认选择。

### 5.3 Real-CUGAN 的 noise 档

`noise` 的含义经常被写反。以 vsmlrt 的源码为准。

| noise | 模型 | 含义 |
|---|---|---|
| -1 | `no-denoise` / `pro-no-denoise3x` | 不降噪，只放大 |
| 0 | `conservative` / `pro-conservative` | 保守修复，设计目标是保真 |
| 1 / 2 | `denoise1x` / `denoise2x` | 仅 2x 支持 |
| 3 | `denoise3x` / `pro-denoise3x` | 最高降噪档 |

`noise=-1` 不是 conservative，`noise=0` 才是。pro 版本目前只有 -1、0、3 三档，且只有 2x、3x。

### 5.4 RIFE 编号

这里容易抄错参数。

| 来源 | 写法 | 25/26 | 4.25/4.26 |
|---|---|---|---|
| `core.rife` | 整数 | 25 = v4.7 ensemble=False；26 = v4.7 ensemble=True | 69/70/71 = 4.25/4.25lite/4.25heavy；72/73 = 4.26/4.26large |
| `vsmlrt.RIFE` | 枚举 | 无 | `v4_25 = 425`，`v4_26 = 426` |
| `video2x` | 字符串 | 无 | `rife-v4.25`、`rife-v4.26` |

Practical-RIFE 的 README 默认推荐 4.25。4.25 的 release note 说动漫场景有明显改善。4.26 的中间帧更敢动，但 issue #110 的对比里鬼影和形变更明显。

本文默认 `model=69`，即 4.25。只有在运动幅度小、需要更顺的镜头里才试 4.26。

### 5.5 FFV1 参数

FFV1 是帧内无损编码。适合做中间格式，因为每帧独立，崩了不用从头来。

```bash
ffmpeg -i input.mkv -c:v ffv1 -level 3 -coder 1 -context 1 \
  -slices 4 -slicecrc 1 -g 1 \
  -pix_fmt yuv444p10le output.mkv
```

| 参数 | 作用 |
|---|---|
| `-level 3` | FFV1 v3，支持 slice 和多线程 |
| `-coder 1` | range coder，压缩率比 golomb 好 |
| `-context 1` | 按平面独立建模 |
| `-slices 4` | 切片并行，切片多会略增体积 |
| `-slicecrc 1` | 每片校验，损坏能定位 |
| `-g 1` | 每帧重置上下文，随机访问更好，压缩率略低 |
| `-pix_fmt yuv444p10le` | 中间文件用 4:4:4，避免色度下采样 |

FFV1 v3 的规范不定义浮点。FFmpeg 9 的 `ffv1` 编码器已经列出 `grayf16le`、`gbrpf16le`、`gbrpf32le` 等浮点格式，FFV1 v4 的草案也在做 sample remapping。但“能编码”不等于“所有工具都能读”，中间文件还是存 10bit 或 16bit YUV 更稳。

空间估算用合成片测过一次：720×480 10bit 4:2:0 约 4 Mbps，1440×1080 10bit 4:2:0 约 18 Mbps，1440×1080 10bit 4:4:4 约 46 Mbps。实片带噪点会更高，先压 10 秒再乘。

### 5.6 x265 参数

x265 的参数解释要以官方文档为准。网上有几条常见说法是反的。

| 参数 | 实际作用 | 本文取值 |
|---|---|---|
| `-pix_fmt yuv420p10le` | 10bit，平坦渐变更不容易出色带 | 使用 |
| `crf=18` | 质量/码率平衡点 | 1080p 动画的起点 |
| `aq-mode=3` | 自适应量化，带暗场偏置 | 3 |
| `aq-strength=0.8` | AQ 强度，默认 1.0 | 0.8 |
| `psy-rd=0.8` | 心理视觉 RD，默认 2.0，0.8 是降低 | 0.8 |
| `psy-rdoq=0.8` | 心理视觉 RDOQ，slow 默认 1.0，0.8 是略降 | 0.8 |
| `deblock=-1,-1` | 降低去块强度，保住线条 | -1,-1 |
| `sao=0` | 关闭 SAO，避免抹平细线 | 0 |

`rd=4` 在 `slow` preset 下是默认值，写不写一样。想要更好的率失真，换 `-preset slower`，不要手动写 `rd=4`。

`psy-rd=0.8` 是降低锐度，不是提高。它适合已经锐化过的放大片，用来收敛过锐和振铃。想要更锐，往 1.2 到 1.5 调。

`--tune animation` 会设置 `psy-rd=0.4`、`aq-strength=0.4`、`deblock=1:1`、`bframes +2`。x265 的 CLI 参数在 preset/tune 之后应用，手写参数会覆盖 tune 的一部分。两个都写不是不行，但要知道自己在覆盖什么。

### 6.3 VMAF

VMAF 测的是编码失真，不是修复质量。它只适合调编码参数，不适合选放大模型。

```bash
ffmpeg -i 01/01_out.mkv -i 01/01_cfr.mkv -lavfi \
  "[0:v]setpts=PTS-STARTPTS[a];[1:v]setpts=PTS-STARTPTS[b];[a][b]libvmaf=log_fmt=json:log_path=vmaf.json" \
  -f null -
```

注意顺序：第一个输入是 distorted，第二个是 reference。常见错误是把参考放在前面，方向反了。

这段命令只用于同帧率对比。本文拿未插帧的编码版本和源比。插帧后的成品是 59.94fps，源是 23.976fps，不要直接跑这条命令。

VMAF 要求两个输入分辨率一致。拿 1440×1080 的成品和 720×480 的源直接比会报错。把成品缩回源分辨率又会引入新的失真，结论不干净。

VMAF 的模型训练集以实拍内容为主。我的经验是，它在动画上的线条、色带、过锐判断不可靠，可能给过锐的版本打高分。本文只用它比较 CRF 和 preset。

## 8. 故障排查

先看错误信息，再查表。不要同时改多个参数。

| 症状 | 可能原因 | 处理 |
|---|---|---|
| `GridSample not supported` | RIFE 跑在 NCNN_VK | 用独立 RIFE 插件 |
| `unsupported operator` | ONNX 算子不被 ncnn 支持 | 查 `model_test.py`，换 ORT/DML 或换模型 |
| `vspipe` 找不到 Python | 没跑 `vapoursynth config` | 执行 `vapoursynth config` |
| 插件找不到 | R74 新目录或路径不对 | 放 `<site-packages>/vapoursynth/plugins` 或设 `VAPOURSYNTH_EXTRA_PLUGIN_PATH` |
| RIFE 找不到模型 | `models` 和 `.so` 不同级 | 放同一级 |
| 输出无声 | vspipe 只传了视频 | 加 `-i 源 -map 1:a?` |
| 整体偏绿或偏红 | 矩阵用错，或帧属性没改 | 改 `_Matrix`，输入 6、输出 1 |
| 等间距细线 | 分块接缝 | 加大 overlap |
| 线条断裂 | 模型容量不足或 tilesize 太小 | 换大模型，加大 overlap |
| 中间帧重影 | RIFE 4.26 或大运动 | 换 4.25，降低倍率 |
| 背景呼吸抖动 | 逐帧模型无时域约束 | 减小锐化，加轻微时域降噪 |
| 画面闪烁 | 逐帧处理放大噪声 | 预处理加 denoise，换更稳的模型 |
| 字幕糊边 | 字幕进了模型链 | 字幕单独处理，最后合 |
| 显存不足 | tilesize 太大 | 降到 512，关闭其他 GPU 程序 |
| `shutdown` 失败 | 没有权限 | 用 root，或删除关机命令 |

先算帧数和磁盘，再决定是否整片跑。

整条链跑 4fps，需要 2.4 小时；跑 1.5fps，需要 6.4 小时。12 集是 29 到 77 小时。

### A.1 `upscale.vpy`

这是主链脚本，包含几何、预处理、放大、插帧和输出。

```python
# 用法:
# vspipe -p -a input=01/01_cfr.mkv -c y4m upscale.vpy - | ffmpeg ...
import vapoursynth as vs
import vsmlrt

core = vs.core
core.max_cache_size = 8192  # MB，按内存调整

# 1. 读源，锁定矩阵和 range
clip = core.bs.VideoSource(input)
clip = core.std.SetFrameProps(clip, _Matrix=6, _Range=0)

# 2. 几何：720×480 -> 720×540
clip = core.resize.Spline36(clip, width=720, height=540)

# 3. 预处理：去色带
clip = core.f3kdb.Deband(
    clip,
    y=48,
    cb=24,
    cr=24,
    grainy=32,
    grainc=16,
    dynamic_grain=False,
)

# 4. 去振铃，按需开启
# clip = core.lghost.LGhost(
#     clip,
#     mode=[1],
#     shift=[5],
#     intensity=[23],
# )

# 5. 转 RGBS，输入矩阵 6
clip = core.resize.Bicubic(
    clip,
    format=vs.RGBS,
    matrix_in=6,
    range_in_s="limited",
)

# 6. 2x 放大
clip = vsmlrt.inference(
    clip,
    network_path="models/2x_AniSD_AC_G6i2b_SPAN_190K_fp32.onnx",
    overlap=(16, 16),
    tilesize=(1024, 1024),
    backend=vsmlrt.Backend.NCNN_VK(fp16=True),
)

# 7. 2.5x 插帧，4.25
clip = core.rife.RIFE(
    clip,
    model=69,
    factor_num=5,
    factor_den=2,
)

# 8. 回 YUV420P10，输出矩阵 1
clip = core.resize.Bicubic(
    clip,
    format=vs.YUV420P10,
    matrix=1,
    range_s="limited",
)

clip.set_output()
```
